## Replacement implications

Keeping each existing WireGuard public key preserves its derived session ID and principal ID. That keeps bridge expected-ID checks, the chatbot MCP audience, and the existing grants aligned. Container names must still match the canonical session UUID for current runit/startup lookups; changing only the display alias does not change the identity.

The checked-in `op-identity-root create` path preserves `user.opdbus.*` identity metadata by archiving the old container, but starts a fresh identity root and empty Cozo device. The older handoff specifically says the chatbot's old Cozo device stays on the archived instance. This preserves authentication identity, not container-local Cozo contents. Central identity/registry/grant stores and host bridge Cozo databases are separate authorities/data stores and are not the disposable container root. No container replacement or cleanup was performed in this task.
