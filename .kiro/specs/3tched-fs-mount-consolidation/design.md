performed. Citations are to source as checked out in `/srv/git/odbus-verified`; runtime/
deployed state is not asserted except where marked as a prior HANDOFF receipt.
Companion: `requirements.md` (R#/C#).
**Spec id:** `3tched-fs-mount-consolidation`

## 0. Architecture Overview

### 0.1 Current State (verified)

The filesystem projection layer is fragmented across three components:

1. **`crates/op-plugins/src/state_plugins/fuse.rs`** (8,046 lines) — libfuse generated types
   (`PLUGIN_NAME = "fuse"`). This file is GENERATED by `gen_fuse.py` from libfuse C headers.
   It contains a duplicate block of filesystem contract types (lines 7692–7808):
   `ContractDescriptor`, `FilesystemContract`, `Invocation`, `FilesystemProtocol`, plus
   a `dispatch_fs_projection()` dispatcher (lines 8027–8037). These contract types are
   identical (non-comment) to those in `_3tched_fs.rs:24–330`.

2. **`crates/op-plugins/src/state_plugins/_3tched_fs.rs`** (561 lines) — the original
   3tchedFS filesystem plugin (`PLUGIN_NAME = "_3tched_fs"`, line 17). Contains
   `ContractDescriptor`, `FilesystemContract`, `Invocation`, `FilesystemProtocol`
   (lines 26–80), the `ThreeTchedFsPlugin` impl of `StatePlugin` (line 173),
   `_3tched_fs_schema()` (line 237), and a dispatch function (line 320). Both
   `get_contract` and `get_protocol` are declared methods.

3. **`deploy/runit/libexec-3tched/mount-3tchedfs`** (131 lines) — the mount helper that:
   - Reads fstab mount source/target to select `--exclude-plugin` or `--include-plugin`
     (line 31–32)
   - Invokes the binary with `--fs-name` and `--exclude-plugin threetched` or
     `--include-plugin threetched` (lines 109–116)
   - Checks view.json readiness: for `threetched` mounts, checks that
     `view.json.objects` keys match `["threetched"]`; for `3tchedFS` mounts, checks
     that `view.json.objects` has `_3tched_fs` (line 86) and the remaining keys
     equal the catalog minus threetched (lines 86–88)

4. **`crates/_3tched-fs/src/main.rs`** — the filesystem binary with CLI:
   - `Mount` subcommand takes `--fs-name` (default "3tchedFS", line 160) but NO surface flag
   - `Capture` subcommand takes `--include-plugin` / `--exclude-plugin`
   - No `--surface` CLI argument exists

### 0.2 Design Goals

- One consolidated plugin schema under `threetched_fs`
- One binary with `--surface` flag selecting between `3tched_fs` and `threetched_fs`
- One mount helper that maps fstab entries to `--surface` values
- Remove all duplicate contract definitions
- Maintain libfuse generation (`fuse.rs` stays as-is, generated)

### 0.3 Key Design Decisions

**Decision D1: Consolidated plugin name is `threetched_fs`**
- Rationale: The user confirmed the name in the Grok session (turns 47–48).
  `_3tched_fs` is the historical name; `threetched_fs` is the canonical name
  going forward. The libfuse plugin remains as `fuse` (generated, separate).
- Impact: Renames `PLUGIN_NAME`, schema function name, module path, and all
  references across op-plugins, _3tched-fs binary, mount helper, and contracts.

**Decision D2: `--surface` flag replaces `--fs-name` as the surface selector**
- Rationale: `--fs-name` currently only sets the kernel-visible mount source label.
  The surface (3tched vs threetched) controls plugin selection, not the label.
- The existing `--fs-name` argument remains as-is for the kernel label; a new
  `--surface` argument controls projection scope.
- `mount` subcommand: `--surface 3tched_fs` → exclude threetched, mount 3tched;
  `--surface threetched_fs` → include only threetched, mount threetched.

**Decision D3: libfuse contract types stay in fuse.rs; filesystem contract types
move to a shared module referenced by both fuse.rs and threetched_fs.rs**
- Rationale: `fuse.rs` is generated by `gen_fuse.py` and should not be hand-edited.
  The filesystem contract types (ContractDescriptor, FilesystemContract, etc.) are
  NOT generated — they are the filesystem projection schema. Extract them to a
  shared module (`filesystem_contract.rs`) that both files can reference.
- `fuse.rs` will reference the shared types to preserve the `dispatch_fs_projection()`
  behavior, but `dispatch_fs_projection` itself is removed (R2.5: no duplicate schema).

**Decision D4: Inode hash includes surface name**
- Rationale: The same logical path on `3tched_fs` and `threetched_fs` mounts must
  produce different inodes (R8.5).
- Current: `inode_for_path(path)` uses `blake3::hash(path)` (namespace.rs:1234).
- New: `inode_for_path(surface, path)` uses `blake3::hash(format!("{surface}{path}"))`.
- No second inode table in SHM; inodes are still computed on-the-fly.

**Decision D5: Mount helper uses `--surface` instead of `--fs-name` + plugin selection**
- Rationale: Consolidates the mount helper into a single decision tree rather than
  two parallel flag combinations.
- `3tchedFS:/run/mounts/3tchedFS` → `--surface 3tched_fs --exclude-plugin threetched`
- `threetched:/run/mounts/threetched` → `--surface threetched_fs --include-plugin threetched`
- Readiness check: look for `threetched_fs` in `view.json.objects` keys for 3tched mounts,
  or check the catalog inclusion logic (same as before, but using the new plugin name).

**Decision D6: threetched binary contract stays separate**
- Rationale: The threetched plugin (ZeroClaw binary) is a separate plugin backed by
  the autonomous `/usr/bin/threetched` executable. This spec only consolidates the
  filesystem projection layer (R1–R5). The threetched plugin schema and contract
  are not modified.

## 1. File-by-file Design

### 1.1 `crates/op-plugins/src/state_plugins/threetched_fs.rs` (renamed from `_3tched_fs.rs`)

**Changes:**

| Change | Before | After |
|--------|--------|-------|
| Module path | `_3tched_fs.rs` | `threetched_fs.rs` |
| `mod` declaration | `pub mod _3tched_fs;` (mod.rs:104) | `pub mod threetched_fs;` |
| `PLUGIN_NAME` | `"_3tched_fs"` | `"threetched_fs"` |
| Schema function | `_3tched_fs_schema()` | `threetched_fs_schema()` |
| Plugin struct | `ThreeTchedFsPlugin` | `ThreetchedFsPlugin` |
| Contract types | Defined inline (lines 26–80) | Imported from shared module |
| Contract import | `use super::_3tched_fs_contract;` | `use super::_3tched_fs_contract;` (unchanged) |

**New shared module: `crates/op-plugins/src/state_plugins/filesystem_contract.rs`**

This new file extracts the duplicate contract types from both `fuse.rs` and
`_3tched_fs.rs` into a single shared module:

```rust
// Filesystem contract types shared by fuse.rs and threetched_fs.rs.
// These are NOT generated; they define the filesystem projection schema.

pub use _3tched_fs_contract::{document, schema_version, source_commit};

// ContractDescriptor, FilesystemContract, Invocation, FilesystemProtocol
// extracted from both fuse.rs:7692-7808 and _3tched_fs.rs:24-80.
// Identical implementations, one source of truth now.
// Includes literal_contract_schema / literal_schema helpers.
```

Both `fuse.rs` and `threetched_fs.rs` replace their inline contract definitions
with `use crate::state_plugins::filesystem_contract::*;`.

**Removed: `dispatch_fs_projection()` in `fuse.rs:8027-8037`**

This dispatcher was the duplicate entry point for filesystem contract methods.
With the consolidated plugin, `get_contract` and `get_protocol` are declared
only on the `threetched_fs` plugin. The `fuse.rs` plugin schema will no longer
include these methods.

**Method declarations:** `get_contract` and `get_protocol` move from the
`threetched_fs` plugin to the consolidated schema. The `fuse.rs` plugin
schema (`fuse_schema()`) no longer includes filesystem contract methods.

### 1.2 `crates/_3tched-fs/src/main.rs`

**New CLI flag: `--surface`**

Add to `Mount` subcommand and to global options:

```rust
#[arg(long)]
surface: Option<String>,
```

- If `surface` is `None`, the mount subcommand errors with a usage message
  listing valid surfaces: `3tched_fs` and `threetched_fs`.
- If `surface == "3tched_fs"`: equivalent to current `--exclude-plugin threetched`
  behavior (R5.1).
- If `surface == "threetched_fs"`: equivalent to current
  `--include-plugin threetched` behavior (R5.2).
- Any other value: error with the unrecognized value in the message.

**Preserve: `--fs-name` remains** for the kernel-visible mount source label
(unchanged). The `--surface` flag controls projection scope, not the label.

**New validation:** After parsing `--surface`, set the FUSE subtype (mount
option) to match the surface name. The subtype determines how the kernel
reports the mount source.

### 1.3 `deploy/runit/libexec-3tched/mount-3tchedfs`

**Updated mount source handling:**

```sh
case "$fs_name:$mount_path" in
    3tchedFS:/run/mounts/3tchedFS) surface=3tched_fs; selection=--exclude-plugin ;;
    threetched:/run/mounts/threetched) surface=threetched_fs; selection=--include-plugin ;;
    *) fail 'unexpected mount source or target' ;;
esac
```

**New binary invocation:**

```sh
# Replace existing invocation (lines 109-116) with:
"$binary" --store "$store" capture --schema-only --catalog "$catalog" \
    --state /dev/shm/opdbus/state --surface "$surface" \
    "$selection" "$upstream_plugins" >"$runtime/capture.json"
nohup setsid "$binary" --store "$store" mount \
    --surface "$surface" \
    --catalog /dev/shm/opdbus/plugin-blobs --state /dev/shm/opdbus/state \
    --allow-other --auto-unmount --call-owner-uid "$owner_uid" \
    --lungs-socket /run/opdbus/lungs/lungs.sock --lungs-session "$session" \
    --fs-name "$fs_name" \
    "$mount_path" >"$runtime/daemon.log" 2>&1 </dev/null 9>&- &
```

**Updated readiness check (lines 74-89):**

```sh
# Replace the _3tched_fs check with threetched_fs:
timeout 3 jq -e --arg name "$surface" --arg upstream "$upstream_plugins" \
    --slurpfile catalog "$catalog/.manifest.json" '
    ($upstream | split(",") | sort) as $upstream |
    (.objects | keys | sort) as $actual |
    (.source_catalog_hash == $catalog[0].catalog_hash and
     .source_catalog_generation == $catalog[0].generation) and
    (if $name == "threetched_fs" then $actual == $upstream
    else (.objects | has("threetched_fs")) and
        ($actual == (($catalog[0].plugins | keys | sort) - $upstream))
    end)
' "$mount_path/view.json" >/dev/null
```

**Key changes:**
- Line 86: `_3tched_fs` → `threetched_fs`
- Line 85: `threetched` → `threetched_fs` (the surface value is now `threetched_fs`)
- Added `--surface "$surface"` to both capture and mount binary invocations

### 1.4 `crates/_3tched-fs/src/namespace.rs`

**Inode function change (line 1234):**

```rust
// Before:
fn inode_for_path(path: &str) -> u64 {
    let bytes = blake3::hash(path.as_bytes()).as_bytes()[..8]
        .try_into().expect("eight-byte slice");
    let mut ino = u64::from_le_bytes(bytes) | (1 << 63);
    if ino == ROOT_INO { ino += 1; }
    ino
}

// After:
fn inode_for_path(surface: &str, path: &str) -> u64 {
    let input = format!("{surface}{path}");
    let bytes = blake3::hash(input.as_bytes()).as_bytes()[..8]
        .try_into().expect("eight-byte slice");
    let mut ino = u64::from_le_bytes(bytes) | (1 << 63);
    if ino == ROOT_INO { ino += 1; }
    ino
}
```

All callers of `inode_for_path(path)` must be updated to pass the surface
name as the first argument. The surface is available from the `Namespace`
struct's mount configuration.

### 1.5 `crates/_3tched-fs/src/source.rs`

No changes required. Source catalog handling is independent of the surface
flag; the catalog path is passed via `--catalog` which the mount helper
still provides.

### 1.6 `crates/op-plugins/src/state_plugins/mod.rs`

```rust
// Before:

// After:
```

### 1.7 `crates/op-plugins/src/state_plugins/_3tched_fs_contract.rs`

No changes. The contract document itself is stable — it describes the

### 1.8 Default registry and schema loading

If `default_registry.rs` or similar registration code references
`_3tched_fs_schema()` or `ThreeTchedFsPlugin`, update to
`threetched_fs_schema()` and `ThreetchedFsPlugin`.

## 3. SHM Representation Changes (R9)

### 3.1 FileSource variants — coverage matrix

| FileSource Variant | 3tched_fs Projection | threetched_fs Projection | Notes |
|--------------------|---------------------|-------------------------|-------|
| `MountMetadata` | Yes | Yes | view.json metadata |
| `View` | Yes | Yes | full view |
| `Workspace` | Yes | Yes | COW workspaces |
| `Object {plugin_id}` | Yes | Yes | plugin object blob |
| `Schema {plugin_id}` | Yes | Yes | plugin schema |
| `Value {plugin_id, pointer}` | Yes | Yes | live state |
| `Capabilities {plugin_id}` | Yes | Yes | plugin capabilities |
| `Hash {plugin_id}` | Yes | Yes | object hash |
| `MethodInput {plugin_id, method}` | Yes | Yes | method input schema |
| `MethodOutput {plugin_id, method}` | Yes | Yes | method output schema |
| `MethodMetadata {plugin_id, method}` | Yes | Yes | method metadata |
| `ThreetchedSchema` | No | Yes | threetched-specific schema |
| `ThreetchedInput/Output/Metadata` | No | Yes | threetched-specific commands |
| `LiveFile {plugin_id, pointer}` | Yes | Yes | live value (read-only) |
| `Symlink` | Yes | Yes | symlinks in namespace |
| `CallFile {plugin_id, method}` | Yes | Yes | call dispatch |

### 3.2 Explicit exclusions

- **Frozen workspace values** on DirectShm backend: returns ENODATA rather than
  silently omitting (R9.6).
- **Catalog blobs** in `/dev/shm/opdbus/plugin-blobs/` are not FileSource
  variants — schemas accessed through `object.blob.json` path (R9.5).
- **Generation metadata** (`Namespace::generation`, `live_generation`): tracked
  but not standalone FileSource projections (R9.3).

### 3.3 Inode changes

- `inode_for_path(surface, path)` — surface name is prefix to hash input
- No inode table stored in SHM (R8.5)
- Existing `ROOT_INO = 1` collision avoidance preserved
- Cross-surface: same path → different inodes (surface name differs)

## 4. Security Considerations

### 4.1 No new identity or grant scope

The `--surface` flag does not create new identities, grants, or credential
paths. Mount identity, session files, and operator UID checks remain
unchanged (mount-3tchedfs lines 50–57).

### 4.2 Surface name validation

The binary validates `--surface` against a whitelist: `3tched_fs` and
`threetched_fs`. No arbitrary values are accepted. This prevents
information disclosure via mount source labels (R1.3).

### 4.3 Contract types

The extracted contract types (`filesystem_contract.rs`) contain no live data,
no credentials, and no secrets. They are pure schema definitions.

## 5. Error Handling

| Error Condition | Error Response |
|-----------------|----------------|
| `--surface` not provided | Usage message listing valid surfaces |
| `--surface` unrecognized | Error: "unrecognized surface: {value}" |
| Mount source unrecognized | Helper: "unexpected mount source or target" |
| `threetched_fs` not in catalog | Mount fails: "expected plugin not found in catalog" |
| DirectShm cannot provide representation | ENODATA or ENOENT (not silent omission) |

## 6. Performance Impact

- **Binary size increase:** < 5% (adding `--surface` flag + inode prefix, removing
  duplicate contract types — net change is minimal)
- **Mount readiness check:** Same as before (< 3 seconds, R9.2)
- **FUSE operation overhead:** No increase — the surface flag selects projection
  scope at startup, not per-request
- **Inode computation:** Same as before — one blake3 hash per path, no cache,
  no table lookup

## 7. Migration Path

### 7.1 Source-only changes (no deploy impact)

All changes are to source files in the repository. No runtime configuration,
grant, or identity changes are required.

### 7.2 Release activation impact

After the source is built and released:

1. The mount helper (`mount-3tchedfs`) reads the new `--surface` parameter
   from the new binary's help text or a staged config file.
2. The readiness check looks for `threetched_fs` instead of `_3tched_fs` in
   `view.json.objects`.
3. fstab entries and mount paths are unchanged.

No compatibility shim is needed — the old plugin name `_3tched_fs` is removed
from the new build, and the readiness check would fail if the old name were
still in the catalog (which it isn't after a fresh build).

### 7.3 Historical references

Files in this repo that reference `_3tched_fs` will be updated to
`threetched_fs` as part of this spec. Historical documentation and comments
are updated for consistency (R6.3).
